# 4. 문제 해결

## 과도한 API 요청에 의한 "302 Too many Request" 문제와 아키텍처 변경

**문제 상황:**
본 웹앱은 사용자가 스팀(Steam) 게임을 선택하여 매칭하는 구조입니다. 초기에는 사용자별로 스팀 API를 직접 호출하여 게임 정보를 가져왔으나, 스팀 측의 API 요청 제한 기준으로 인해 `"302 Too many Request"` 에러가 발생하여 서비스를 정상적으로 이용할 수 없는 문제가 발생했습니다.

**해결 과정:**
API 요청 사이에 지연 시간을 두는 등 여러 시도를 했으나, 실제 운영 환경에서는 근본적인 해결책이 될 수 없다고 판단했습니다. 

**결과 (아키텍처 변경):**
결국 외부 API 실시간 호출 방식을 폐기하고, **미리 게임 관련 정보를 DB에 적재해 두고 사용자가 이를 조회하는 아키텍처**로 전면 수정했습니다. 
이 변경을 통해 외부 API(Steam)와의 결합을 끊어내고, DB 조회를 통해 응답 속도를 향상시키며 안정적인 운영이 가능한 환경이 되었습니다.

## 2.5 WebSocket을 통한 실시간 채팅 기능 및 STOMP를 활용한 수신자/발신자 라우팅
 HTTP 기반 메시징에 **WebSocket**을 결합하여 실시간 메시지 수신을 구현하고, **STOMP 프로토콜**로 수신자/발신자별 메시지 라우팅을 처리했습니다.
 <br>
**설계 의도**
- HTTP 폴링 방식의 불필요한 네트워크 오버헤드를 제거하고, 양방향 실시간 통신 구현
- STOMP 프로토콜의 구독(Subscribe) 기반 라우팅으로 사용자별 메시지 정확히 전달
- WebSocket 연결에도 JWT 인증을 적용하여 보안 일관성 유지
<br>

**WebSocket 구성**
| 설정 | 값 | 설명 |
|------|-----|------|
| STOMP 엔드포인트 | `/ws-nearby-gamers` | WebSocket 핸드셰이크 진입점 |
| 메시지 브로커 | `/queue`, `/topic` | 1:1 큐, 브로드캐스트 토픽 |
| 애플리케이션 접두사 | `/app` | 클라이언트 → 서버 메시지 경로 |
| 유저 접두사 | `/user` | 사용자별 개인 큐 라우팅 |
| Fallback | SockJS | WebSocket 미지원 브라우저 대응 |

<br>

**메시지 라우팅 흐름** <br>
[발신자 → 서버] : <br>
STOMP SEND /app/chat.send → MessageController에서 수신 → MessageService: DB 저장 + 수신자 확인 → SimpMessagingTemplate: /user/{receiverId}/queue/messages 로 전달

[수신자 ← 서버] : <br>
STOMP SUBSCRIBE /user/queue/messages → 구독 중인 수신자에게 실시간 메시지 도착

**WebSocket JWT 인증 처리** <br>
[STOMP CONNECT 단계] → WebSocketAuthChannelInterceptor.preSend() 실행 → Authorization 헤더에서 Bearer Token 추출 → Redis 블랙리스트 확인 → 무효화 토큰이면 연결 거부 → JwtTokenUtil로 서명 + 만료 검증 → UserDetailsService로 사용자 조회 → SecurityContext + StompHeaderAccessor에 인증 정보 설정 → 인증 실패 시 WebSocket 연결 자체를 차단

**기술적 특징**
- `ChannelInterceptor`를 활용한 STOMP 레벨 JWT 인증 (HTTP 필터와 분리된 별도 보안 계층)
- `/user` 접두사로 Spring이 자동으로 사용자별 큐를 생성/관리
- SockJS Fallback으로 WebSocket 미지원 환경 대응
- HTTP 인증(JwtAuthenticationFilter)과 WebSocket 인증(WebSocketAuthChannelInterceptor)이 동일한 `JwtTokenUtil` + `TokenService`를 공유 → 인증 로직 일관성 보장
